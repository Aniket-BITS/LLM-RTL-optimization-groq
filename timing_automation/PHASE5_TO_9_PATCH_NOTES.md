# Phase 5–9 patch notes

This snapshot implements the revised rule that diagnostic classification controls prompt specificity, not optimizer eligibility.

- Phase 5: `select_sat` and `case_physical` are first-class analysis stages. Residual reconvergence is allowed to continue as diagnostic uncertainty.
- Phase 6: optimizer packets contain request-ready guided and exploratory units. Recommended focus ranges/patterns are advisory.
- Phase 7: candidate mutation authority is the exact SourceBundle; the linter no longer rejects safe edits merely for falling outside recommended focus.
- Phase 8: mode-aware closure-attempt driver added. Guided recommendation exhaustion falls back to exploratory requests. For cumulative promotion, the driver deliberately stops at the promotion boundary and requires fresh analysis before another iteration so stale timing evidence is never reused.
- Phase 9: stable-select SAT, case-analysis witness construction, physical case reporting and exact-signature physical resolution are integrated into `run_analysis.py`; unsupported evidence stays exploratory and never causes a guessed attribution.

Hard safety boundaries intentionally retained: source hashes, SourceBundle membership, module ownership, frozen/protected policy, formal equivalence, physical recipe/stage identity and PPA promotion policy.
